Method notes (honest):
- The greeter dropped QMP-injected keys this boot, so the test session was
  started by pointing greetd's default_session at cosmos-session (runtime
  guest edit only; no repo files touched). Compositor/shell memory metrics
  are unaffected.
- heaptrack 1.5.0+dfsg1-5 installed in-guest via apt (apt-get update needed —
  the image ships no package index).
- Session script wrapped at runtime only (cosmos-session.orig restored after):
  `heaptrack -o /tmp/heap-<name> <binary> ...`. Compositor finalized with
  SIGINT; cosmos-shell ignores SIGINT — SIGTERM used instead.
- Release profile has strip=true, so heaptrack's raw output is addresses.
  Symbol names below were resolved host-side against an unstripped rebuild
  (CARGO_PROFILE_RELEASE_STRIP=none CARGO_TARGET_DIR=target/release-dbg
  cargo build --release; zero repo edits) using each process's live
  /proc/pid/maps file-offset mapping + addr2line -f -C.
- heaptrack_print -p sorts sites by allocation CALL COUNT; the lists here are
  re-sorted by peak bytes. Frame lists are the merged sub-backtraces of a
  site, so several distinct allocation paths share one entry. Optimized
  (lto) code inlines a lot — a few addr2line attributions look suspicious;
  reported as-is.
